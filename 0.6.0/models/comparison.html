ModelSpec, ColumnTransformer, patsy and formulaic#

ModelSpec builds model matrices, as do sklearn’s ColumnTransformer, patsy and formulaic. The two formula libraries parse a string such as 'Sales ~ Price * ShelveLoc' in the spirit of R’s model formulae. A ColumnTransformer lists a transformer and the columns it applies to, for each block of columns. ModelSpec takes a list of Python objects: column names, tuples for interactions, and features that wrap any sklearn transformer.

This page compares them on flexibility and extensibility: what it takes to add a new kind of term, to nest one feature inside another, to interact terms, and to work inside sklearn. Reproducing R’s formula semantics is not a goal of ModelSpec, so some defaults differ on purpose; those are collected at the end.

The ISLP helpers are accessed as islp.poly, islp.ns, etc. rather than imported by name. Formula strings are evaluated in the calling namespace, so importing ISLP’s bs would silently replace patsy’s bs inside patsy.dmatrix('bs(Price, df=5)', ...).

Fitting a ModelSpec fits copies of the encoders of its terms, so the same terms can be used in several specifications, and a fitted specification can be fit again. The same in patsy and formulaic#

Both formula libraries support stateful transforms, but an sklearn transformer needs a wrapper written against each library’s protocol.

from formulaic.transforms import stateful_transform

class _PatsySklearn:
    # patsy's stateful transform protocol, wrapping an sklearn transformer
    def __init__(self):
        self.chunks = []
    def memorize_chunk(self, *cols, est):
        self.est = est
        self.chunks.append(np.column_stack(cols))
    def memorize_finish(self):
        self.est_ = clone(self.est).fit(np.vstack(self.chunks))
    def transform(self, *cols, est):
        return self.est_.transform(np.column_stack(cols))

patsy_sk = patsy.stateful_transform(_PatsySklearn)

@stateful_transform
def formulaic_sk(*cols, est, _state=None):
    X = np.column_stack(cols)
    if 'est' not in _state:
        _state['est'] = clone(est).fit(X)
    return _state['est'].transform(X)

spl = SplineTransformer(n_knots=5)
X_patsy = patsy.dmatrix('patsy_sk(Price, est=spl) + ShelveLoc', Carseats)
X_formulaic = formulaic.model_matrix('formulaic_sk(Price, est=spl) + ShelveLoc', Carseats)
X_ms = MS([spline, 'ShelveLoc'], intercept=True).fit_transform(Carseats)
X_patsy.shape, X_formulaic.shape, X_ms.shape

((400, 10), (400, 10), (400, 10))

Working inside scikit-learn#

A ModelSpec is an sklearn transformer, so it can be the first step of a Pipeline, and refit on each fold of a cross-validation. Here the regression fits its own intercept, so the model matrix has none:

pipe = make_pipeline(MS(['Price', 'ShelveLoc', 'Income'], intercept=False),
                     LinearRegression())
cross_val_score(pipe, Carseats, Carseats['Sales'], cv=5).round(3)

array([0.54 , 0.458, 0.618, 0.581, 0.55 ])

Tuning the parameters of terms#

The parameters of each term are parameters of the ModelSpec, so GridSearchCV can tune them as it tunes those of any sklearn estimator. A term’s parameter is named by the position of the term in terms:

key

the parameter of

'terms__<i>__<parameter>'

the term at position i, e.g. 'terms__0__df'

'terms__<i>__<j>__<parameter>'

part j of the interaction at position i

'terms__<name>__<parameter>'

the term given that name, e.g. ns('Price', df=4, name='price')

get_params() lists them:

spec = MS([islp.ns('Price', df=4),
           'US',
           ('ShelveLoc', islp.poly('Income', 2))], intercept=False)
{k: v for k, v in spec.get_params().items()
 if k in ('terms__0__df', 'terms__2__1__degree')}

{'terms__0__df': 4, 'terms__2__1__degree': 2}

In a Pipeline each key is prefixed by the name of its step, here 'modelspec__'. Both parameters are tuned below. A term made by ns(), bs(), poly() or pca() is made again with its new parameters, so its name, and the names of its columns, follow:

pipe = make_pipeline(spec, LinearRegression())
grid = {'modelspec__terms__0__df': [1, 2, 4, 8],
        'modelspec__terms__2__1__degree': [1, 2, 3]}
search = GridSearchCV(pipe, grid, cv=5).fit(Carseats, Carseats['Sales'])
best = search.best_estimator_[0]
search.best_params_, best.terms[0].name, best.terms[2][1].name

({'modelspec__terms__0__df': 1, 'modelspec__terms__2__1__degree': 1},
 'ns(Price, df=1)',
 'poly(Income, degree=1)')

The parameters of other terms, e.g. a derived_feature of any transformer or contrast(), are those of their encoder ('terms__<i>__n_knots' for a SplineTransformer, 'terms__<i>__method' for contrast()). Setting a parameter does not change terms: it is replaced by a copy, in which a term used in several places, e.g. also in an interaction, is changed in all of them.

So can terms itself, to choose among specifications:

grid = {'modelspec__terms': [['Price', 'ShelveLoc'],
                             ['Price', 'ShelveLoc', ('Price', 'ShelveLoc')]]}
search = GridSearchCV(make_pipeline(MS(intercept=False), LinearRegression()),
                      grid, cv=5)
search.fit(Carseats, Carseats['Sales'])
len(search.best_params_['modelspec__terms'])

Compared with scikit-learn’s ColumnTransformer#

A ColumnTransformer fits as naturally into sklearn as a ModelSpec: it is a transformer, and the parameters of its transformers can be tuned. The same model matrix, a spline in Price, ShelveLoc and Income, is written below both ways; they give the same columns, and tuning the number of knots of the spline gives the same results.

from sklearn.compose import ColumnTransformer, make_column_selector
from sklearn.preprocessing import OneHotEncoder, PolynomialFeatures

spline = islp.derived_feature(['Price'], encoder=SplineTransformer(n_knots=5),
                              name='spline')
ms = MS([spline, 'ShelveLoc', 'Income'], intercept=False)

ct = ColumnTransformer([
    ('spline', SplineTransformer(n_knots=5), ['Price']),
    ('shelve', OneHotEncoder(drop='first', sparse_output=False), ['ShelveLoc']),
    ('income', 'passthrough', ['Income'])])

searches = {
    'ModelSpec': GridSearchCV(make_pipeline(ms, LinearRegression()),
                              {'modelspec__terms__0__n_knots': [3, 5, 8]}, cv=5),
    'ColumnTransformer': GridSearchCV(make_pipeline(ct, LinearRegression()),
                                      {'columntransformer__spline__n_knots': [3, 5, 8]}, cv=5)}
for name, search in searches.items():
    search.fit(Carseats, Carseats['Sales'])
    print(f'{name:18s}', search.best_params_, search.cv_results_['mean_test_score'].round(4))

ModelSpec          {'modelspec__terms__0__n_knots': 3} [0.5483 0.5409 0.5457]
ColumnTransformer  {'columntransformer__spline__n_knots': 3} [0.5483 0.5409 0.5457]

The categorical ShelveLoc needs its own encoder in the ColumnTransformer, chosen by name or, as here, by dtype; a ModelSpec codes it from its dtype.

ct_by_dtype = ColumnTransformer([
    ('spline', SplineTransformer(n_knots=5), ['Price']),
    ('categorical', OneHotEncoder(drop='first', sparse_output=False),
     make_column_selector(dtype_include='category')),
    ('income', 'passthrough', ['Income'])])
ct_by_dtype.fit_transform(Carseats[['Price', 'ShelveLoc', 'Income']]).shape

(400, 10)

Interactions are where the two differ most. In a ModelSpec a tuple interacts any terms, here the spline with ShelveLoc. A ColumnTransformer has no way to multiply one block of columns by another: PolynomialFeatures(interaction_only=True) multiplies every pair of its input columns, including pairs of spline columns and of dummy columns.

ms_interaction = MS([spline, 'ShelveLoc', (spline, 'ShelveLoc')], intercept=False)
ct_interaction = make_pipeline(
    ColumnTransformer([('spline', SplineTransformer(n_knots=5), ['Price']),
                       ('shelve', OneHotEncoder(drop='first', sparse_output=False), ['ShelveLoc'])]),
    PolynomialFeatures(degree=2, interaction_only=True, include_bias=False))
print('ModelSpec        ', ms_interaction.fit_transform(Carseats).shape[1], 'columns')
print('ColumnTransformer', ct_interaction.fit_transform(Carseats).shape[1], 'columns')

ModelSpec         23 columns
ColumnTransformer 45 columns

Sparse model matrices#

With sparse_output=True, a ModelSpec returns a scipy.sparse.csr_matrix. Categorical encodings and their interactions are built sparse throughout, so a categorical with many levels never forms its dense columns; formulaic’s output='sparse' does the same. Here a categorical with 5,000 levels and 50,000 rows, whose dense model matrix would take 2 GB:

rng = np.random.default_rng(0)
n, K = 50_000, 5_000
B = pd.DataFrame({'x': rng.standard_normal(n),
                  'id': pd.Categorical(rng.integers(0, K, n).astype(str))})
X_ms = MS(['x', 'id', ('id', 'x')], intercept=True,
          sparse_output=True).fit_transform(B)
X_formulaic = formulaic.model_matrix('x + id + id:x', B, output='sparse')
print('ModelSpec', type(X_ms).__name__, X_ms.shape, f'{X_ms.nnz:,} nonzero')
print('formulaic', type(X_formulaic).__name__, X_formulaic.shape, f'{X_formulaic.nnz:,} nonzero')

formulaic ModelMatrix (50000, 9998) 199,974 nonzero

Model structure#

All three record which columns of the model matrix belong to each term, which is what an ANOVA or a group-wise selection procedure needs.

design = MS(['Price', 'ShelveLoc', ('Price', 'ShelveLoc')], intercept=True).fit(Carseats)
print('ModelSpec', {str(k): (v.start, v.stop) for k, v in design.column_map_.items()})
print('patsy    ', {k: (v.start, v.stop) for k, v in
                    patsy.dmatrix('Price*ShelveLoc', Carseats).design_info.term_name_slices.items()})
print('formulaic', {str(k): v for k, v in
                    formulaic.model_matrix('Price*ShelveLoc', Carseats).model_spec.term_indices.items()})

def same_columns(A, B):
    A, B = np.asarray(A, float), np.asarray(B, float)
    return A.shape == B.shape and all(any(np.allclose(a, b) for b in B.T) for a in A.T)

ModelSpec’s column of ones is set to change: intercept=True is its default only until ISLP 0.7, when ModelSpec moves to its own package and the default becomes intercept=False, as for a ColumnTransformer. Pass intercept=True for statsmodels’ models (OLS, GLM, …), which need the column, and intercept=False for sklearn and glmstar estimators, which fit their own intercept; the examples on this page pass it explicitly for this reason.

Ordered categoricals are coded with contrasts by ModelSpec, patsy and formulaic. ModelSpec can instead score one by the position of its level with ordinal(), which requires an explicit order: an ordered categorical (or a polars Enum), or levels=[...].

Where the others go further#

  • Syntax. A formula is shorter than the equivalent list of terms. ModelSpec relies on Python to generate lists of terms instead.

  • R’s coding rules. Both recode the terms of a formula, e.g. an interaction without its main effects, to keep the model matrix full rank, as R does; ModelSpec codes each term as given.

  • Native backends. formulaic materializes a model matrix from a polars or pyarrow frame directly; ModelSpec converts the columns it uses to pandas first, copying them.

  • Speed and memory. For 2,000,000 rows, two numeric columns and a categorical of 50 levels (a dense model matrix of 0.83 GB), formulaic built the model matrix in 0.1 s with 0.9 GB of memory besides the data; ModelSpec and a ColumnTransformer took about 0.5 s and 1.7 GB, holding the largest block of columns and the model matrix at once.

  • No extra dependency. A ColumnTransformer is part of sklearn, with its own conventions for naming columns (get_feature_names_out) and choosing them (make_column_selector).
