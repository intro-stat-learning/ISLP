__init__(method='drop', drop_level=None)#

Contrast encoding for categorical variables.

Parameters:
method[‘drop’, ‘sum’, None, callable]

If ‘drop’, then a column of the one-hot encoding will be dropped. If ‘sum’, then the sum of coefficients is constrained to sum to 1. If None, the full one-hot encoding is returned. Finally, if callable, then it should take the number of levels of the category as a single argument and return an appropriate contrast of the full one-hot encoding.

drop_levellevel identifier (optional)

If not None, this level of the category will be dropped if method is ‘drop’ (or given coefficient minus the sum of the others if ‘sum’). Matched against the levels by value, then by str.

Levels are those observed when fit, in the order of
the categories for a categorical dtype and sorted
otherwise; unused categories are dropped. Missing
values give a row of `np.nan`, and a level not seen
when fit raises a `ValueError` on transform.

ModelSpec#

class ISLP.models.model_spec.ModelSpec(terms=(), intercept=None, categorical_features=None, categorical_encoders=None, sparse_output=False)#

Bases: TransformerMixin, BaseEstimator

Parameters:
termssequence (optional)

Sequence of sets whose elements are columns of X when fit. For pd.DataFrame these can be column names.

interceptbool or None (optional)

Include a column of ones named ‘intercept’ as the first column of the design? Pass True for statsmodels’ models (OLS, GLM, …), which need the column, and False for estimators that fit the intercept themselves (glmstar’s estimators and most scikit-learn estimators). The default, None, behaves as True but issues a FutureWarning at fit: the default will change to False in ISLP 0.7, when ModelSpec moves to its own package.

categorical_featuresarray-like of {bool, int} of shape (n_features)

or shape (n_categorical_features,), default=None.

Indicates the categorical features. Will be ignored if X is a pd.DataFrame or pd.Series.

  • None : no feature will be considered categorical for np.ndarray.

  • boolean array-like : boolean mask indicating categorical features.

  • integer array-like : integer indices indicating categorical features.

categorical_encodersdict (optional)

Encoders for the categorical columns of X, i.e. the columns of categorical dtype of a pd.DataFrame or those given by categorical_features for an np.ndarray. Its keys are either:

  • ‘categorical’ : the encoder of every categorical column, ordered or not, without its own entry, cloned for each column. Defaults to Contrast(method=’drop’), which drops the first level.

  • ‘ordinal’ : if present, used instead for the ordered pd.Categorical columns, e.g. {‘ordinal’: Ordinal()} to score each by the position of its level. No default.

  • a column of X (a name for a pd.DataFrame, an integer for an np.ndarray) : the encoder of that column. Like the others it is cloned, and the clone is fit, so the dictionary’s encoders are not modified.

For an encoder of a single term, see contrast() and ordinal().

sparse_outputbool (optional)

If True, the model matrix is a scipy.sparse.csr_matrix. Categorical encodings and their interactions are then built sparse throughout, so a design with categoricals of many levels never forms its dense columns; other columns (numeric, splines, etc.) are dense blocks stored sparsely. Not compatible with set_output.

Get parameters of this ModelSpec.

set_params(**params)#

Set parameters of this ModelSpec.

A parameter of a term is set with ‘terms__<i>__<parameter>’, where i is the position of the term in terms or the name given to it, e.g. ‘terms__price__df’ for ns(‘Price’, df=4, name=’price’). A term made by poly(), ns(), bs() or pca() is made again with the new parameter, so its name (if not given) and its columns’ names follow it. terms itself is not modified: it is replaced by a copy, in which every occurrence of the changed term (e.g. also in an interaction) is changed.
